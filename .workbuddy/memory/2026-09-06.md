## 回退：用户决定放弃嘴部改动（同日稍后）

用户原话：「先放弃嘴巴部分的修改吧，也不要微笑和开合了，用之前的版本」。

### 改动

在 `qingya_rig.py` 顶部加两个开关（默认 False）：

```python
ENABLE_MOUTH_KEYS = False   # 不生成 mouth_open / smile 形态键
ENABLE_ORAL_PARTS = False   # 不合并牙齿 / 舌头 / 口腔贴片
```

- `build_shape_keys()` 开头：`if not ENABLE_MOUTH_KEYS: return made`（在眨眼/眯眼之后、嘴部之前早退）
- `main()`：`merge_teeth_into(obj) if ENABLE_ORAL_PARTS else None`
- 输出改为 `qingya_3d_v4_clean.glb`（独立文件，保留带嘴版可对比）

前端同步清理：
- `qingya_rig_bundle.js`：删除嘴部自动动画段（`ye`/`Se`/`ge`/`be`/`Fe`），`ue("mouth_open",...)`/`ue("smile",...)` 一并移除，只留 `if(S)` 手动接管循环；删除 `ne("btn-mouth",...)` 事件注册（否则 `getElementById` 返回 null 会抛错中断初始化）
- `qingya_rig_template.html`：删除「嘴巴」开关按钮、「张嘴」「微笑」两个滑块，视角按钮挪到第三行，标题改为「骨骼绑定版（无嘴部）」

### 教训

给形态键/几何件加**总开关**比直接删代码好——用户改变主意时能一键切回。以后类似「先试试看」的需求都应该这么做。
